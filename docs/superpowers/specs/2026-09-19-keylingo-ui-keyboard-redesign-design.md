# KeyLingo UI 및 양손 키보드 재설계

작성일: 2026-09-19

## 목적

현재 KeyLingo는 기능과 정보 구조는 완성되어 있지만, 평면적인 카드와 키보드 표현 때문에 제품의 핵심인 타건 감각이 충분히 드러나지 않는다. 이번 재설계는 키보드를 화면의 주인공으로 만들고, 휴대폰을 양손으로 잡은 상태에서 엄지로 누르기 편한 하단 입력 영역을 제공한다.

최종 시각 방향은 **프리미엄 아케이드**다. KeyLingo의 차분한 파란색과 학습 앱의 명료함을 유지하면서, Roblox의 `+1 Speed Keyboard Clicker`에서 보이는 큰 키 구조와 즉각적인 보상감을 절제해서 적용한다. 원본 게임의 화면 구성이나 자산을 복제하지 않는다.

## 성공 기준

- 키보드는 콘텐츠 안의 평면 카드가 아니라 화면 하단에 결합된 실제 입력 장치처럼 보인다.
- 375px 폭 휴대폰에서 키보드 몸체가 가용 폭의 약 96%를 사용하고 좌우 여백은 8px를 기준으로 한다.
- 키를 누르면 윗면이 6~7px 내려가고, 옆면과 그림자가 줄어 눌림 깊이가 즉시 보인다.
- 입력, 오디오, 햅틱, 시각 반응이 `onPressIn` 시점에 함께 시작된다.
- 홈, 학습, 결과, 컬렉션, 설정 화면이 같은 색상·타이포그래피·표면 규칙을 사용한다.
- 한글 두벌식, 영문 QWERTY, 문장용 보조 키, Shift, Backspace 동작을 그대로 유지한다.
- 키별 래스터 이미지는 사용하지 않는다. 화면 크기와 테마가 달라도 코드 기반 키캡이 선명하게 확장되어야 한다.

## 시각 방향

### 전체 UI

배경은 현재의 밝은 청백색 계열을 유지하되, 단색 면을 줄이고 약한 광원 그라데이션을 사용한다. 네이비는 텍스트와 주요 행동에 사용하고, 밝은 하늘색은 진행 상태와 눌림 피드백에 사용한다. 카드 테두리는 줄이고 높이 차이, 배경 명도, 얕은 그림자로 계층을 만든다.

타이포그래피는 제목과 숫자의 대비를 강화한다. 학습 프롬프트와 입력 문자열은 가장 큰 시각 요소로 유지하고, 모드명·콤보·진행률은 작고 압축된 HUD로 표현한다. 장식용 대형 아이콘이나 화면마다 다른 색상 체계는 추가하지 않는다.

홈 화면은 일일 목표와 시작 행동을 하나의 중심 영역으로 묶는다. 학습 모드 카드는 아이콘, 제목, 한 줄 설명, 잠금 상태만 표시한다. 결과 화면은 점수와 획득 보상을 큰 숫자로 보여주되 키보드의 시각적 존재감을 넘지 않는다. 컬렉션은 키보드 테마 미리보기가 실제 키캡 구조를 공유하도록 바꾼다.

### 키보드

각 키는 다음 세 층으로 구성한다.

1. **스위치/바닥층:** 눌렀을 때 잠깐 드러나는 가장 어두운 층이다.
2. **키캡 옆면층:** 기본 상태에서 6~7px의 높이를 만들며 테마의 중간 명도를 사용한다.
3. **키캡 윗면층:** 글자, 상단 하이라이트, 미세한 명도 변화를 포함한다.

기본 상태에서는 윗면이 위로 올라와 있고 옆면과 낙하 그림자가 보인다. 누른 상태에서는 윗면을 아래로 이동하고 그림자 높이를 1px로 줄인다. 눌린 키의 색상과 얕은 외곽 광원을 함께 바꿔 색각이나 애니메이션 중 하나만으로 상태를 전달하지 않도록 한다.

키별 PNG, WebP 또는 다른 래스터 이미지는 사용하지 않는다. 이미지는 다양한 문자, 키 폭, 테마, 화면 배율에 대응하기 어렵다. 향후 재질감이 필요하면 상호작용하지 않는 키보드 몸체에만 5% 이하의 노이즈 텍스처를 선택적으로 사용할 수 있다.

## 양손 그립 레이아웃

학습 화면은 `Screen`의 공통 22px 좌우 패딩을 키보드에 적용하지 않는다. 텍스트 콘텐츠는 기존 읽기 폭을 유지하고, 키보드 도크만 별도의 전체 폭 영역으로 렌더링한다.

- 휴대폰 폭 320~480px: 좌우 8px 여백을 기준으로 가용 폭의 약 96% 사용
- 더 넓은 화면: 키보드 폭을 최대 560px로 제한하고 중앙 정렬
- 키 높이: 기본 42px, 작은 화면에서는 최소 39px
- 열 간격: 3~4px
- 행 간격: 8px
- 두 번째 행: 좌우 8px 안쪽 정렬
- Shift와 Backspace: 일반 키의 약 1.45~1.5배 폭
- 하단: 키보드 몸체 색상을 안전 영역까지 이어 시각적으로 하나의 장치로 연결

키보드는 학습 화면의 가장 아래에 고정된 구조로 배치하되, 운영체제의 실제 safe-area inset을 침범하지 않는다. 홈 인디케이터가 있는 기기에서는 키보드 몸체 아래에 inset만큼의 색상 연결 영역을 둔다. 작은 높이의 기기에서는 프롬프트 영역의 여백을 먼저 줄이고, 키 높이를 최소값 아래로 축소하지 않는다.

엄지 도달 범위는 사용자에게 상시 표시하지 않는다. 설계 및 QA 기준으로만 사용하며, 가장자리 문자 키와 Shift/Backspace가 양쪽 엄지의 자연스러운 범위에 오도록 배치한다.

## 입력 피드백과 모션

키 입력은 다음 순서로 처리한다.

1. `onPressIn`에서 키 눌림 애니메이션, 사운드, 햅틱을 즉시 시작한다.
2. 기존 `onKey` 콜백으로 문자 또는 제어 키를 전달한다.
3. 입력 상태가 갱신되면 입력 문자열과 ghost suffix를 다시 그린다.
4. 정답이면 해당 키 위에 짧은 광원과 작은 보상 피드백을 표시한다.
5. `onPressOut` 또는 포인터 취소 시 키를 기본 높이로 복귀시킨다.

모션 기준은 다음과 같다.

- 눌림: 60~80ms
- 복귀: 90~120ms
- 키 이동 거리: 기본 7px
- 광원: 180~240ms
- 문자 또는 `+1` 팝업: 450~600ms, 동시에 최대 3개
- 정답 전체 피드백: 500ms 이내에 다음 행동을 방해하지 않도록 종료

일반 학습 모드에서는 입력한 문자 또는 작은 빛만 표시한다. Speed와 Rain 모드에서는 `+1` 또는 콤보 증가를 사용할 수 있다. 모든 화면에 큰 `+1`을 반복해 학습 내용을 가리지 않는다.

`reducedMotion` 설정이나 운영체제의 Reduce Motion이 활성화되면 이동, 확대, 팝업을 끈다. 눌린 색상과 명도 변화는 남겨 입력 상태를 확인할 수 있게 한다.

## 컴포넌트 구조

### 디자인 시스템

`src/design-system/theme.ts`에 화면 색상과 키보드 테마를 분리한 토큰을 추가한다.

- 화면: 배경 광원, 주요/보조 표면, 텍스트, 구분선, 성공·오류·보상
- 키보드: deck top, deck side, key top, key side, key pressed, legend, glow
- 모션: press depth, press duration, release duration, feedback duration
- 치수: 화면 패딩, keyboard inset, key gap, row gap, radius

기존 테마 ID와 잠금·가격 정보는 유지한다. 각 테마에 입체 표현용 색상을 추가하되 기존 저장 데이터는 마이그레이션하지 않아도 기본값으로 동작하도록 한다.

### `Keycap`

새로운 `src/components/Keycap.tsx`는 하나의 키 모양과 눌림 상태만 담당한다.

- 입력: label, accessibilityLabel, width weight, theme, disabled, reducedMotion, onPressIn
- 출력: 접근 가능한 `Pressable`
- 내부: 스위치층, 옆면층, 윗면층, legend
- 의존성: React Native, Reanimated

애니메이션은 Reanimated shared value로 UI 스레드에서 실행한다. 키마다 React state를 만들지 않아 빠른 연타 시 전체 키보드가 다시 렌더링되는 일을 피한다.

### `Keyboard`

`src/components/Keyboard.tsx`는 키 배열, Shift 상태, 오디오 호출, 문자 전달을 담당한다. 현재 언어별 배열과 입력 의미는 유지하고 시각 렌더링을 `Keycap`에 위임한다.

키보드 몸체와 안전 영역 연결은 `KeyboardDock` 내부 단위로 분리하거나 `Keyboard`의 명확한 하위 뷰로 구현한다. 이 영역은 키 행의 치수 계산과 키보드 테마 적용만 담당한다.

### `KeyFeedbackLayer`

짧은 문자·보상 팝업은 키보드 위에 포인터 이벤트를 받지 않는 단일 오버레이로 표시한다. 키캡마다 별도 오버레이를 두지 않는다. 최대 3개 이벤트를 보관하고 시간이 지나면 제거한다. 화면을 벗어나는 가장자리 키에서는 팝업 위치를 안쪽으로 제한한다.

### 공통 UI

`src/components/ui.tsx`는 버튼, 카드, 화면, 하단 내비게이션의 표면과 눌림 규칙을 통일한다. 공통 버튼도 2~3px의 짧은 깊이 변화는 사용하지만, 키보드보다 강한 입체감을 사용하지 않는다.

학습 화면은 콘텐츠 패딩과 키보드 도크 패딩을 분리하기 위해 전용 레이아웃을 사용한다. 데이터 및 라우팅 로직은 기존 `Practice`에 유지한다.

## 화면별 변경 범위

### 학습 및 Rain

- 키보드를 하단 전체 폭 도크로 변경
- 프롬프트, 답안, 진행률을 상단 절반에 집중
- 콤보와 남은 시간을 작은 HUD로 통일
- 정답, 오류, 타임아웃 피드백이 키보드 애니메이션과 겹치지 않게 표시
- 일시정지와 나가기 오버레이는 새 표면 토큰 사용

### 홈

- 일일 목표, 연속 학습, 레벨을 하나의 중심 진행 영역으로 재구성
- 시작 버튼을 명확한 주요 행동으로 유지
- 모드 카드는 높이와 정보량을 줄이고 키보드 테마와 같은 입체 규칙을 약하게 사용
- 기존 모드 잠금 및 라우팅 동작 유지

### 결과

- 정확도, 랭크, WPM을 우선순위에 따라 정렬
- 획득 XP와 토큰을 짧은 보상 모션으로 표시
- 다시 하기와 홈으로 가기 행동을 명확히 분리

### 컬렉션 및 설정

- 테마 미리보기는 실제 `Keycap` 구조를 축소해 재사용
- 잠김, 가격, 선택 상태는 색상과 텍스트를 함께 사용
- 설정 행과 스위치는 새 표면·간격 토큰으로 정리

### 온보딩

- 기존 단계와 문구는 유지
- 마지막 단계에서 새 키보드의 눌림을 한 번 직접 체험하게 함
- 튜토리얼 완료 데이터와 분석 이벤트는 변경하지 않음

## 상태와 데이터 흐름

이번 작업은 프로필, 경제, 콘텐츠, 숙련도, 세션 저장 형식을 변경하지 않는다. 새로 추가되는 키 눌림과 팝업 상태는 일시적인 화면 상태이며 저장하지 않는다.

현재 흐름인 `Keyboard → onKey → Practice typing state → score/feedback`은 그대로 유지한다. 시각 피드백은 이 흐름을 관찰하거나 입력 직전에 시작할 뿐, 정답 판정과 세션 기록에 관여하지 않는다. 따라서 애니메이션 실패나 저사양 기기에서도 입력과 점수 계산은 계속 동작해야 한다.

## 오류 및 경계 상황

- 포인터가 키 밖으로 이동하거나 입력 중 화면이 비활성화되면 눌림 상태를 즉시 해제한다.
- 일시정지, 정답 피드백, 화면 이탈 중에는 키보드 입력과 새 팝업을 차단한다.
- 빠른 연타에서 팝업은 최대 3개만 유지하고 오래된 항목부터 제거한다.
- 작은 화면에서 키보드가 잘리면 콘텐츠 여백과 프롬프트 크기를 먼저 줄인다.
- 웹의 그림자와 네이티브 elevation 차이는 플랫폼별 스타일로 맞추되 키 이동 거리와 색상 상태는 동일하게 유지한다.
- 사운드 또는 햅틱이 실패해도 키 입력과 애니메이션은 계속 동작한다.

## 접근성

- 각 키의 기존 `accessibilityRole`, `accessibilityLabel`, `testID`를 유지한다.
- Shift, Backspace, Space는 번역된 이름을 사용한다.
- 눌림, 정답, 오류는 색상 하나에만 의존하지 않는다.
- Reduce Motion을 존중한다.
- 일반 행동 버튼은 최소 44px 높이를 유지한다.
- 키보드 글자는 테마 배경과 충분한 대비를 유지하며 테마별 검증 대상에 포함한다.

## 검증 계획

### 자동 검증

- 기존 단위·통합 테스트로 입력 조합, Shift, Backspace, 정답 판정 회귀 확인
- `Keycap` 네이티브 컴포넌트 테스트로 접근성 라벨과 press callback 확인
- 타입 검사와 린트 실행
- 웹 번들 및 Android/iOS export 확인
- Playwright로 320×568, 375×667, 430×932에서 주요 화면 흐름 확인

### 시각 검증

- 기본, 눌림, disabled, correct, error 상태 캡처
- Starter, Creamy, Deep Thock, Midnight 테마에서 명도와 그림자 확인
- 한글, 영문, 문장 키보드에서 행 폭과 가장자리 잘림 확인
- 작은 화면에서 키보드 하단과 safe area 연결 확인
- Reduce Motion 상태에서 이동 없이 상태 변화가 전달되는지 확인

## 구현 순서

1. 디자인 토큰 확장
2. `Keycap`과 키보드 도크 구현
3. 기존 `Keyboard` 입력 로직 연결
4. `Practice`와 `RainPractice` 레이아웃 적용
5. 홈과 공통 UI 표면 적용
6. 결과, 컬렉션, 설정, 온보딩 적용

## 범위 제외

- 새 학습 모드 추가
- 콘텐츠, 점수, 경제 밸런스 변경
- 새 오디오 팩 제작
- 계정, 동기화, 결제 구조 변경
- 키별 이미지 자산 제작
- 가로 화면 전용 키보드 또는 태블릿 전용 분할 키보드

## 결정된 사항

- 시각 방향: 프리미엄 아케이드
- 보상 표현: 일반 모드에서는 절제된 문자/빛, Speed·Rain에서는 `+1` 허용
- 키보드 배치: 화면 하단, 약 96% 폭, 8px 기준 좌우 여백
- 키 구현: 이미지가 아닌 코드 기반 3층 키캡
- 입력 대상: 휴대폰을 양손으로 잡고 엄지로 누르는 세로 화면
